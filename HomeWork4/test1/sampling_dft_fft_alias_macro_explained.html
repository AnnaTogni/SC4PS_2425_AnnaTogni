Macro Companion

Detailed Explanation of sampling_dft_fft_alias_macro.C

This document explains, in detail, every major step of the ROOT macro sampling_dft_fft_alias_macro.C in HomeWork4/test1. The macro is designed to build a continuous signal from user-provided frequencies, sample it, compute its spectrum with both a direct DFT and an FFT, measure the execution time of the two approaches, and visualize the result in a six-panel canvas.

Big Picture

What the macro is trying to teach

Sampling

The macro turns a mathematically continuous signal into values on a uniform time grid.

Aliasing

If an input frequency lies above the Nyquist limit, the code computes the frequency that will be observed after sampling.

DFT vs FFT

The code compares the direct mathematical definition of the DFT with a faster radix-2 FFT implementation.

Conceptually, the macro follows this sequence:

  1. Ask the user which sinusoidal frequencies build the signal.
  2. Ask how fast the signal is sampled.
  3. Compute the Nyquist frequency.
  4. Generate the sampled data.
  5. Compute the spectrum in two different ways.
  6. Measure how long those methods take.
  7. Plot both time-domain and frequency-domain views.

Constant

kPi

constexpr double kPi = 3.14159265358979323846;

This defines a high-precision numerical value of π. The keyword constexpr means the value is known at compile time. It is used throughout the code for sinusoidal functions and Fourier phase factors.

Signal Builder

SignalValue: constructing the continuous input signal

double SignalValue(double t, const std::vector<double>& freqs) {
  double value = 0.0;
  for (double f : freqs) {
    value += std::sin(2.0 * kPi * f * t);
  }
  return value;
}

This function defines the physical input signal. The signal is built as a sum of pure sine waves:

s(t) = Σ sin(2π f_i t)

Each frequency entered by the user contributes one sinusoidal component with unit amplitude and zero phase. If the user enters frequencies f1, f2, and f3, the resulting signal is the superposition of all three.

The macro does not currently ask for amplitudes or phases. That means every component contributes equally and starts with the same phase convention.

Aliasing Rule

AliasFrequency: folding frequencies into the observable band

double AliasFrequency(double f, double fs) {
  if (fs <= 0.0) {
    return 0.0;
  }

  double wrapped = std::fmod(std::fabs(f), fs);
  if (wrapped < 0.0) {
    wrapped += fs;
  }
  if (wrapped > fs / 2.0) {
    wrapped = fs - wrapped;
  }
  return wrapped;
}

This function takes an input frequency f and computes how it appears once the signal is sampled at frequency fs. The basic idea is that after sampling, frequencies are only distinguishable inside the Nyquist band:

0 ≤ f_observed ≤ f_s / 2

The function works in two stages:

  1. It first wraps the frequency modulo fs, because sampled spectra repeat every sampling frequency.
  2. If the wrapped value lies above fs/2, it reflects it back into the Nyquist interval.

So if fs = 16 Hz and the input contains 11 Hz, then the function returns 5 Hz, which matches the familiar aliasing rule.

FFT Preparation

IsPowerOfTwo and NextPowerOfTwo

bool IsPowerOfTwo(int n) {
  return n > 0 && (n & (n - 1)) == 0;
}

This function checks whether the number of samples is a power of two. The bit trick (n & (n - 1)) == 0 is true only for numbers like 8, 16, 32, 64, and so on. 

int NextPowerOfTwo(int n) {
  int power = 1;
  while (power < n) {
    power <<= 1;
  }
  return power;
}

The FFT implementation used in this macro is a radix-2 FFT. That algorithm requires a number of samples of the form N = 2^m. If the user-selected duration and sampling frequency produce a different N, this helper raises it to the next valid power of two.

Direct Transform

ComputeNaiveDFT: the literal DFT formula

for (int k = 0; k < n; ++k) {
  std::complex<double> sum(0.0, 0.0);
  for (int m = 0; m < n; ++m) {
    const double angle = -2.0 * kPi * k * m / n;
    sum += samples[m] * std::complex<double>(std::cos(angle), std::sin(angle));
  }
  spectrum[k] = sum;
}

This function implements the DFT directly from its mathematical definition:

X[k] = Σ x[m] exp(-i 2π k m / N)

There are two nested loops:

  • The outer loop chooses the Fourier bin k.
  • The inner loop sums the contribution of every sample x[m].

This is the most transparent way to compute the DFT, because it matches the formula exactly. It is also slow for large N, because it needs roughly N² complex operations.

Direct Inverse

ComputeInverseDFT: reconstructing the sampled signal

for (int m = 0; m < n; ++m) {
  std::complex<double> sum(0.0, 0.0);
  for (int k = 0; k < n; ++k) {
    const double angle = 2.0 * kPi * k * m / n;
    sum += spectrum[k] * std::complex<double>(std::cos(angle), std::sin(angle));
  }
  reconstructed[m] = sum.real() / n;
}

This is the inverse DFT:

x[m] = (1 / N) Σ X[k] exp(+i 2π k m / N)

The sign in the exponential changes, and the final result is divided by N. The macro keeps only the real part because the original input signal is real-valued.

The purpose of this function is didactic: it demonstrates that if the transform is computed correctly, the original sampled sequence can be reconstructed from its Fourier coefficients.

Fast Transform

ComputeFFT: the radix-2 Cooley-Tukey style algorithm

This function computes the same mathematical object as the DFT, but much faster. Its output is still the Fourier spectrum X[k]. The only difference is the algorithmic strategy.

Step 1: promote real samples to complex numbers

for (int i = 0; i < n; ++i) {
  spectrum[i] = std::complex<double>(samples[i], 0.0);
}

FFT butterflies act naturally on complex numbers, so the code first stores each real sample as a complex number with zero imaginary part.

Step 2: bit-reversal reordering

int j = 0;
for (int i = 1; i < n; ++i) {
  int bit = n >> 1;
  while (j & bit) {
    j ^= bit;
    bit >>= 1;
  }
  j ^= bit;
  if (i < j) {
    std::swap(spectrum[i], spectrum[j]);
  }
}

This is the permutation stage required by the iterative radix-2 FFT. The array is reordered into bit-reversed order so that later butterfly combinations can be performed in place.

Step 3: butterfly stages

for (int len = 2; len <= n; len <<= 1) {
  const double angle = -2.0 * kPi / len;
  const std::complex<double> wLen(std::cos(angle), std::sin(angle));
  for (int i = 0; i < n; i += len) {
    std::complex<double> w(1.0, 0.0);
    for (int k = 0; k < len / 2; ++k) {
      const std::complex<double> u = spectrum[i + k];
      const std::complex<double> v = spectrum[i + k + len / 2] * w;
      spectrum[i + k] = u + v;
      spectrum[i + k + len / 2] = u - v;
      w *= wLen;
    }
  }
}

This is the heart of the FFT. The transform is built progressively by combining small transforms into larger ones. At each stage, pairs of values are mixed by the so-called butterfly operations.

Because each stage reuses results from previous stages, the algorithm reduces the cost from O(N²) to O(N log N).

Fast Inverse

ComputeInverseFFT: inverse transform using conjugation

The inverse FFT is implemented by reusing the forward FFT structure. The key identity is:

IFFT(X) = (1 / N) conj( FFT( conj(X) ) )

That is exactly what this function does:

  1. Copy the spectrum.
  2. Conjugate every complex number.
  3. Run the same radix-2 machinery.
  4. Conjugate again and divide by N.

As in the inverse DFT case, the code returns only the real part because the original signal is real.

Spectrum Scaling

BuildAmplitudeSpectrum: converting complex coefficients into plotted amplitudes

const int nPositive = n / 2 + 1;
...
double scale = 2.0 / n;
if (k == 0 || (n % 2 == 0 && k == n / 2)) {
  scale = 1.0 / n;
}
amplitudes[k] = scale * std::abs(spectrum[k]);

The DFT and FFT return complex coefficients. To plot a magnitude spectrum, the macro takes the absolute value |X[k]| and applies a scaling factor.

For a real signal, positive and negative frequency components come in symmetric pairs, so for most bins the amplitude is doubled. The exceptions are:

  • k = 0, the DC component,
  • the Nyquist bin when N is even.

Those do not have a distinct mirrored partner, so they are not doubled.

This is the key quantity that determines the time spacing:

The duration determines how long the signal is observed. Together with the sampling frequency, it determines the number of samples:

The code also checks for invalid inputs and exits early if the user provides nonsense values such as negative frequencies or non-positive duration.

Sample Count

Choosing N and adapting it for the FFT

int nSamples = static_cast<int>(std::lround(duration * samplingFrequency));

This estimates the number of uniformly spaced samples that fit into the requested duration. The code then requires at least 8 samples, which is a very modest lower bound to avoid degenerate cases. 

if (!IsPowerOfTwo(nSamples)) {
  const int requestedSamples = nSamples;
  nSamples = NextPowerOfTwo(nSamples);
  ...
}

If the result is not a power of two, the code increases N to the next valid radix-2 size. This slightly changes the effective sampled duration because the time step remains fixed while the number of points changes.

This is an important implementation detail: the macro prioritizes compatibility with the radix-2 FFT over keeping the originally implied duration exact.

Sampling Summary

Computing the central sampling quantities

const double dt = 1.0 / samplingFrequency;
const double nyquistFrequency = samplingFrequency / 2.0;
const double effectiveDuration = static_cast<double>(nSamples) * dt;

These are the three central sampling outputs:

  • dt: spacing between consecutive samples.
  • nyquistFrequency: highest frequency that can be represented without ambiguity.
  • effectiveDuration: actual duration of the sampled record after any power-of-two adjustment.

The macro prints all of this to the terminal so the user can immediately see the numerical setup.

Aliasing Report

Checking which frequencies survive faithfully

for (double f : inputFreqs) {
  const double alias = AliasFrequency(f, samplingFrequency);
  const bool aliased = f > nyquistFrequency;
  ...
}

This loop compares each original input frequency to the Nyquist frequency. If the original frequency is larger than f_N, the macro reports the folded-back frequency. Otherwise it reports that the component remains observable at its original value.

This is pedagogically important: the macro distinguishes between the true physical content of the original signal and the frequency content that the sampled data is capable of representing.

Continuous and Sampled Data

Creating two time representations of the same signal

Dense continuous-looking curve

const int nContinuousPoints = std::max(2000, 20 * nSamples);
...
signalContinuous.push_back(SignalValue(t, inputFreqs));

The macro builds a dense set of points to mimic the appearance of a continuous signal in the first plot. This is only for visualization. It is not the sampled dataset used for the Fourier analysis.

Actual sampled sequence

for (int n = 0; n < nSamples; ++n) {
  timeSamples[n] = n * dt;
  sampledSignal[n] = SignalValue(timeSamples[n], inputFreqs);
}

This is the actual discretized signal. These are the points used by both the DFT and the FFT. Each sample lies on a uniform time grid.

Timing

Measuring the cost of each transform

const auto dftStart = std::chrono::high_resolution_clock::now();
...
const auto dftStop = std::chrono::high_resolution_clock::now();

The code uses std::chrono::high_resolution_clock to measure elapsed wall-clock time. It times not only the forward transform, but also the inverse reconstruction, so each method is measured as a full transform-and-rebuild cycle. 

const std::chrono::duration<double, std::milli> dftTime = dftStop - dftStart;
const std::chrono::duration<double, std::milli> fftTime = fftStop - fftStart;

The output is given in milliseconds. This helps illustrate the main practical reason FFTs are important.

Frequency Axis

From bin index to physical frequency

for (std::size_t k = 0; k < freqAxis.size(); ++k) {
  freqAxis[k] = static_cast<double>(k) * samplingFrequency / static_cast<double>(nSamples);
}

The transform naturally produces indices k = 0, 1, 2, .... To plot a physically meaningful spectrum, the code converts those indices into frequencies:

f_k = k f_s / N

This is the discrete frequency grid associated with a uniformly sampled record.

Canvas Layout

Why the canvas is divided into 2 columns and 3 rows

auto* canvas = new TCanvas(...);
canvas->Divide(2, 3);

The macro uses six panels to show the same story from complementary angles.

Pad Content Purpose
1 Continuous input + sampled points Shows what the original signal looks like and how it is discretized.
2 Original frequencies, aliased frequencies, Nyquist line Explains which frequencies are physically present and which are observable after sampling.
3 Reconstruction from direct DFT Shows that the explicit DFT and inverse DFT recover the sampled sequence.
4 Magnitude spectrum from direct DFT Displays the frequency content as computed by the slow exact formula.
5 Reconstruction from FFT Shows that the FFT-based route recovers the same sampled signal.
6 Magnitude spectrum from FFT Lets the user compare the FFT result directly with the DFT spectrum.
Axis Scaling

How the code chooses vertical ranges

const double timeMax = 1.2 * std::max({...});
const double freqMax = 1.25 * std::max({...});

These lines choose plot ranges automatically. The code finds the largest absolute time-domain value and the largest spectral amplitude, then adds some margin so the curves do not sit directly on the frame edges.

Pad 1

Input signal in the time domain

The first pad overlays:

  • a smooth blue line for the dense “continuous” curve,
  • red markers for the actual sampled points.

This lets the user visually compare the continuous signal to the discrete sampling lattice.

Pad 2

Input and aliased frequencies

The second pad is not a computed spectrum. It is a conceptual diagram. The code draws:

  • blue vertical lines and markers for the original frequencies,
  • red dashed vertical lines and markers for the aliased frequencies,
  • a green dashed line at the Nyquist frequency.

This panel is especially useful because it separates the physical signal definition from the numerical observation process.

Pads 3 and 5

Reconstructed time-domain signals

The third and fifth pads compare the sampled signal with the sequence reconstructed from:

  • the direct DFT,
  • the FFT.

If everything is implemented correctly, the reconstructed curves should lie on top of the sampled data. This is a strong internal consistency check.

Pads 4 and 6

Frequency-domain spectra

The fourth and sixth pads plot the amplitude spectra from the two methods. The x-axis is limited to the interval from 0 to the Nyquist frequency:

0 ≤ f ≤ f_s / 2

That is the physically meaningful one-sided spectrum for a real-valued sampled signal. In a correct implementation, the DFT and FFT panels should match.

Educational Meaning

What the macro demonstrates as a scientific computing exercise

Sampling theory

The macro makes the Nyquist limit concrete by forcing the user to choose f_s and then showing the consequence for each input frequency.

Aliasing

Frequencies above Nyquist do not simply disappear. They reappear at lower frequencies and can be mistaken for genuine low-frequency structure.

DFT

The explicit DFT exposes the exact formula and reminds the user what the transform really is mathematically.

FFT

The FFT shows that the same result can be obtained much more efficiently by exploiting structure in the problem.

Limitations

Important details that are worth noticing

  • The signal uses only unit-amplitude sine waves with zero phase.
  • The FFT implementation requires a power-of-two sample count.
  • If the sample count is adjusted upward, the effective duration changes.
  • The plotted frequency markers in the upper-right panel are conceptual markers, not measured spectral amplitudes.
  • The code plots only the one-sided amplitude spectrum, which is appropriate for real signals.
Summary

One concise interpretation of the whole macro

The macro is a compact teaching laboratory for the full chain continuous signal → sampling → Nyquist limit → aliasing → DFT → FFT → visualization. Its strongest feature is that it does not only compute spectra: it also explains, through its output and canvas layout, why those spectra look the way they do.
